# تحكم TOTOLINK ND300 — تطبيق Android

تطبيق Kotlin + Jetpack Compose (Material 3، RTL عربي بالكامل) يتحكم في مودم
TOTOLINK ND300 عبر لوحة إدارته على الشبكة المحلية (HTTP)، ويجدول أوامر تلقائية
(إيقاف/تشغيل الإنترنت) باستخدام AlarmManager + WorkManager، بدون أي Relay أو
قطع كهرباء خارجي.

## ⚠️ نقطة مهمة جداً — لماذا لا توجد أوامر جاهزة داخل التطبيق؟

لا يوجد توثيق رسمي موحّد وموثوق لواجهة برمجة (API) خاصة بطراز **ND300** تحديداً.
طرازات TOTOLINK المختلفة تستخدم واجهات ويب مختلفة (بعضها القديم يستخدم نماذج HTML
تقليدية بمصادقة Session/Cookie، وبعض الطرازات الأحدث تستخدم `cstecgi.cgi` بنمط
`action=xxx&token=yyy`). بدلاً من افتراض أوامر قد لا تعمل فعلياً على جهازك، صُمم
التطبيق حول **محرك قوالب طلبات HTTP قابل للتعديل بالكامل من داخل شاشة "الإعداد"**:

- أنت (أو أي شخص تثق به تقنياً) تلتقط الطلبات **الحقيقية** التي يرسلها متصفحك
  فعلياً عند استخدام لوحة إدارة المودم (خطوات الالتقاط أدناه).
- تُدخل هذه الطلبات (Path / Method / Body / مؤشر النجاح) في شاشة الإعداد.
- `RouterController` في التطبيق ينفّذ هذه القوالب **حرفياً** دون أي تخمين.
- توجد أيضاً إمكانية تحميل "قالب مرجعي" مبني على نمط `cstecgi.cgi` الموثّق
  علنياً في تحليلات لطرازات TOTOLINK أخرى (A3300R, X5000R, X6000R) — لكنه
  **غير مؤكد لـ ND300** ومُعلَّم بتحذير واضح داخل الواجهة، ويجب اختباره وتعديله.

هذا هو الالتزام الصريح بشرطك: **"لا تخترع API أو روابط غير موجودة"**.

## 1) دليل التقاط الطلبات الحقيقية من متصفحك

1. اتصل بجهاز كمبيوتر بنفس شبكة Wi-Fi/LAN الخاصة بالمودم.
2. افتح المتصفح (Chrome مثلاً) واذهب إلى `http://192.168.1.1` (أو عنوان المودم لديك).
3. اضغط `F12` لفتح أدوات المطوّر، وافتح تبويب **Network**، وفعّل خيار
   "Preserve log" حتى لا يختفي السجل عند إعادة تحميل الصفحة.
4. سجّل الدخول بلوحة الإدارة بشكل طبيعي، وراقب أول طلب POST/GET يُرسل
   (عادة إلى صفحة أو ملف `login` أو `cgi-bin/...`). انسخ:
   - الـ Method (GET أو POST)
   - الـ Path الكامل (بعد اسم المضيف)
   - محتوى الـ Body (إن وجد)، وأي Headers خاصة (مثل `Referer` أو `X-Requested-With`)
   - الكوكيز التي أعادها المودم (التطبيق يتعامل معها تلقائياً عبر CookieJar داخلي)
5. اذهب إلى صفحة التحكم بالإنترنت/WAN/Wi-Fi في لوحة الإدارة، واضغط الزر الذي
   يعطّل الاتصال، وسجّل الطلب المُرسل بنفس الطريقة. كرّر لزر التفعيل وزر
   إعادة التشغيل (Reboot).
6. انسخ كل طلب إلى الحقول المطابقة في شاشة "الإعداد" داخل التطبيق (تسجيل
   الدخول / إيقاف الإنترنت / تشغيل الإنترنت / إعادة التشغيل).
7. إن كانت الاستجابة تحتوي نصاً ثابتاً يدل على النجاح (مثل `"result":"0"` أو
   `success`)، ضَعه في حقل "نص يدل على النجاح" لتتأكد الأوامر اللاحقة من نجاحها فعلاً.

> ملاحظة: بعض واجهات TOTOLINK القديمة تستخدم HTTP Basic Authentication بدل
> صفحة تسجيل دخول HTML — في هذه الحالة ضع اسم المستخدم/كلمة المرور في الرابط
> نفسه أو أضف Header بصيغة `Authorization: Basic <base64>` (التطبيق يدعم
> إضافة Headers مخصصة لكل قالب).

## 2) بنية المشروع

```
app/src/main/java/com/nd300/controller/
├── MainActivity.kt                 نقطة الدخول + التنقل السفلي + RTL
├── TotolinkApp.kt                  Application (تهيئة قناة الإشعارات)
├── data/
│   ├── db/                         Room: الجداول + السجل
│   ├── repository/                 طبقة الوصول للبيانات
│   └── security/SecureStorage.kt   EncryptedSharedPreferences (Android Keystore)
├── network/
│   ├── RequestTemplate.kt          نموذج قالب الطلب القابل للتعديل
│   ├── RouterConfig.kt / RouterController.kt / RouterActionResult.kt
│   ├── CommonTemplates.kt          قالب مرجعي غير مؤكد + قالب فارغ
│   └── TemplateJson.kt             حفظ/قراءة القوالب كـ JSON
├── scheduler/
│   ├── AlarmScheduler.kt           جدولة AlarmManager دقيقة وذاتية التجديد
│   ├── ScheduleAlarmReceiver.kt    يستقبل التنبيه وينفّذ عبر WorkManager
│   ├── RouterActionWorker.kt       تنفيذ فعلي + إعادة محاولة + تسجيل + إشعار
│   └── BootReceiver.kt             إعادة الجدولة بعد إعادة التشغيل/تغيير الوقت
├── notifications/NotificationHelper.kt
└── ui/                             شاشات Compose (الرئيسية، الجداول، السجل، الإعداد)
```

**الأمان:** كلمة المرور واسم المستخدم والقوالب تُخزَّن فقط داخل
`EncryptedSharedPreferences` المبنية على Android Keystore (تشفير AES-256).
لا توجد كلمة مرور مكتوبة في الكود، ولا تُطبع في أي `Log`.

**الموثوقية:** AlarmManager (`setExactAndAllowWhileIdle`) يضمن التنفيذ حتى في
وضع Doze/توفير البطارية، ويُعاد بناء كل الجداول تلقائياً بعد إعادة تشغيل
الهاتف أو تغيير الوقت/المنطقة الزمنية (`BootReceiver`). عند فشل التنفيذ
(فقدان اتصال، فشل تسجيل دخول، تأخر شبكة) يعيد `RouterActionWorker` المحاولة
حتى 3 مرات بفاصل تصاعدي، ثم يسجّل الفشل ويرسل إشعاراً بالسبب.

## 3) بناء APK — الطريقة الأسهل: GitHub Actions (تلقائي، مجاني، بدون أوامر)

يحتوي المشروع على `/.github/workflows/build.yml` جاهز يبني APK تلقائياً على
خوادم GitHub في كل مرة تدفع فيها كوداً (push) إلى المستودع:

1. أنشئ مستودعاً جديداً فارغاً على GitHub (Public أو Private).
2. ارفع محتويات مجلد `nd300` بالكامل إليه (اسحب وأفلت الملفات عبر واجهة
   GitHub في المتصفح، أو عبر `git push` إن كنت معتاداً عليه).
3. اذهب لتبويب **Actions** في المستودع — سترى العملية "Build ND300 Controller APK"
   تعمل تلقائياً (تستغرق عادة 3-6 دقائق).
4. بعد اكتمالها بنجاح (علامة ✅)، افتح العملية واضغط على
   **nd300-controller-debug-apk** أسفل قسم "Artifacts" لتنزيل ملف APK جاهز
   للتثبيت مباشرة على هاتفك.

هذه أوثق طريقة للحصول على APK فعلي وقابل للتشغيل، لأن خوادم GitHub تملك
وصولاً كاملاً لكل مستودعات Android الرسمية (Google Maven، Gradle) بعكس بعض
بيئات التطوير المحلية المقيّدة الشبكة.

## 4) بناء APK باستخدام Termux (على جهاز Android مباشرة، بديل يدوي)

> ملاحظة: هذا المشروع **لا يتضمن** ملف `gradle-wrapper.jar` الثنائي (تعذّر
> تنزيله من بيئة الإعداد التي أنشأت المشروع). لذلك أسهل طريقة داخل Termux هي
> تثبيت Gradle مباشرة عبر `pkg` واستخدام أمر `gradle` بدل `./gradlew` —
> أو تشغيل `gradle wrapper` مرة واحدة لتوليد الملف الثنائي بنفسك إن أردت.

```bash
# 1) ثبّت الحزم الأساسية داخل Termux
pkg update && pkg upgrade -y
pkg install -y openjdk-17 git wget unzip gradle

# 2) فعّل الوصول للتخزين ثم انسخ مجلد المشروع (nd300) إلى Termux
termux-setup-storage
cp -r /sdcard/Download/nd300 ~/nd300
cd ~/nd300

# 3) حمّل Android SDK command-line tools (مرة واحدة فقط)
mkdir -p ~/android-sdk/cmdline-tools
cd ~/android-sdk/cmdline-tools
wget https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip
unzip commandlinetools-linux-11076708_latest.zip
mv cmdline-tools latest
cd ~/nd300

# 4) عرّف متغيرات البيئة
export ANDROID_SDK_ROOT=~/android-sdk
export PATH=$PATH:$ANDROID_SDK_ROOT/cmdline-tools/latest/bin:$ANDROID_SDK_ROOT/platform-tools

# 5) ثبّت الحزم المطلوبة ووافق على التراخيص
yes | sdkmanager --licenses
sdkmanager "platform-tools" "platforms;android-34" "build-tools;34.0.0"

# 6) ابنِ APK باستخدام Gradle المثبّت عبر pkg
gradle assembleDebug

# (اختياري) لتوليد gradlew حقيقي يعمل بدون تثبيت gradle يدوياً لاحقاً:
# gradle wrapper --gradle-version 8.7
# ثم استخدم ./gradlew assembleDebug في المرات القادمة

# الناتج سيكون في:
# app/build/outputs/apk/debug/app-debug.apk
```

لبناء نسخة إصدار (release) موقّعة، أضف ملف `keystore` وأعدّ `signingConfigs`
في `app/build.gradle.kts`، ثم شغّل `gradle assembleRelease`.

> إذا واجهت بطء أو نفاد ذاكرة داخل Termux على هاتف بموارد محدودة، يمكن بدلاً
> من ذلك فتح نفس مجلد المشروع مباشرة في Android Studio على كمبيوتر وبناء
> APK من هناك (File → Open → اختر مجلد nd300).

## 5) طريقة إعداد التطبيق مع TOTOLINK ND300

1. افتح التطبيق → تبويب **"الإعداد"**.
2. أدخل عنوان IP الخاص بالمودم (افتراضياً `192.168.1.1` أو `192.168.0.1` حسب
   الطراز/الإصدار)، واسم المستخدم وكلمة المرور (افتراضياً `admin` / `admin`
   إن لم تُغيَّرا).
3. اتبع "دليل التقاط الطلبات" أعلاه واملأ قوالب: تسجيل الدخول، قراءة الحالة،
   إيقاف الإنترنت، تشغيل الإنترنت، إعادة التشغيل.
4. اضغط **"اختبار الاتصال"** — سيحاول التطبيق الوصول للمودم ثم تسجيل الدخول
   بالقالب الذي أدخلته، ويعرض لك النتيجة (نجاح / سبب الفشل بالتفصيل).
5. اضغط **"حفظ"**.

## 6) طريقة اختبار أمر التشغيل والإيقاف

1. من الشاشة الرئيسية اضغط **"إيقاف الإنترنت"**.
2. تحقق فعلياً من جهاز آخر متصل بنفس الشبكة أن الإنترنت انقطع (وليس فقط أن
   التطبيق أظهر رسالة نجاح — قد يختلف مؤشر النجاح الفعلي حسب استجابة مودمك،
   لذلك اضبط حقل "نص يدل على النجاح" بدقة حسب ما رأيته في أدوات المطوّر).
3. اضغط **"تشغيل الإنترنت"** وتحقق من عودة الاتصال.
4. افتح تبويب **"السجل"** للتأكد من أن العملية سُجّلت بحالة "نجح"، وراجع
   "السبب" إن ظهرت "فشل".
5. لاختبار الجدولة: أنشئ جدولاً بوقت إيقاف بعد دقيقتين من الوقت الحالي ووقت
   تشغيل بعد 4 دقائق، فعّل اليوم الحالي فقط، ثم أغلق التطبيق تماماً من قائمة
   التطبيقات الأخيرة وانتظر — يجب أن يعمل الأمر رغم إغلاق الواجهة، وتظهر
   إشعارات بالنتيجة.

## 7) الفرق بين خيارات التحكم (كما أوضحه الطلب الأصلي)

| الإجراء | ما الذي يحدث فعلياً |
|---|---|
| **إيقاف/تشغيل الإنترنت** | يُنفَّذ عبر قالب `disableInternet` / `enableInternet` الذي تحدده أنت — وهو غالباً تعطيل WAN أو Wi-Fi حسب ما يوفره الفريموير فعلياً (يُعرض لك أيهما في شاشة الإعداد) |
| **إعادة تشغيل المودم** | أمر منفصل تماماً (`reboot`) ولا يُستخدم أبداً كبديل تلقائي لإيقاف/تشغيل الإنترنت |
| **إيقاف الجهاز بالكامل** | غير مدعوم عمداً — خارج نطاق الطلب، ويتطلب فعلياً قطع كهرباء لا تحكماً برمجياً |

## 8) الصلاحيات المطلوبة ولماذا

- `INTERNET` / `ACCESS_NETWORK_STATE` / `ACCESS_WIFI_STATE`: التواصل مع لوحة
  إدارة المودم على الشبكة المحلية.
- `SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM`: تنفيذ الجدول في الوقت المحدد
  بدقة رغم توفير البطارية.
- `RECEIVE_BOOT_COMPLETED`: استعادة الجداول بعد إعادة تشغيل الهاتف.
- `POST_NOTIFICATIONS`: إشعارك بنجاح/فشل التنفيذ التلقائي.
- `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_DATA_SYNC`: يدعمها WorkManager
  عند الحاجة لتنفيذ موثوق في الخلفية.

للحصول على أفضل موثوقية، يُستحسن أيضاً استثناء التطبيق من "تحسين البطارية"
يدوياً من إعدادات النظام (بعض الشركات المصنّعة — مثل Xiaomi/Huawei/Oppo —
تفرض قيوداً إضافية غير قياسية على تطبيقات الخلفية).
